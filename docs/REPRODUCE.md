# Reproduction

Run from the release root with Python 3.11. Install `requirements.txt`; a tested
local package-version record is retained under `docs/validation/` after verification.
These version ranges are supported environment targets, not a claim that all
combinations have been tested. CPU with four threads is the recorded formal setting.

## Public data to prepared inputs

```bash
python -m src.pipeline prepare --data-root /external/SpaceNet2 --work runs/full
```

The command discovers public assets by their original filenames, checks frozen
RGB/label hashes, applies the four recorded derived repairs and regenerates Support
using RGB-PanSharpen, PAN, MUL-PanSharpen and native MUL evidence. It checks all regenerated Support class arrays against
`configs/support_array_sha256.json`. The historical manifest's support fraction is
projected-area based and is not substituted for a native pixel fraction. The original data remain
external and unchanged. `runs/full/manifest.csv` contains runtime resolved paths and
must not be published. The 2160-scene manifest is a frozen research input: using it
reproduces the actual split without retrospectively searching for a new split.

## Formal training and routes

```bash
python scripts/reproduce.py --work runs/full --stage train
python scripts/reproduce.py --work runs/full --stage evaluate
python scripts/reproduce.py --work runs/full --stage gis
```

The first command generates 12 models (two cities × two architectures × three
seeds), per-epoch logs/checkpoints and source-only normalization. The second runs
24 route/architecture/seed tests and exports native probability, binary and error
GeoTIFFs plus per-scene confusion/ellipsoidal-area ledgers. GIS uses native class
polygons projected to city UTM, lexicographic overlap ownership, three scales and
four origins. It emits 288 sets of cell statistics and 27 diagnostics per set.

One explicit source/route example:

```bash
python -m src.pipeline train --work runs/full --architecture UNet --city AOI_3_Paris --seed 20261115
python -m src.pipeline evaluate --work runs/full --architecture UNet --route B --seed 20261115
python -m src.pipeline gis --work runs/full --architecture UNet --route B --seed 20261115
```

Do not run the individual examples after the full commands in the same output
directory: existing outputs deliberately cause an error. Training saves every epoch
so another researcher can audit the selected checkpoint. Weights are generated
locally, never downloaded from an author's private computer.

## Formal figure layouts

```bash
python scripts/figures.py --figure 3
python scripts/figures.py --figure 5
```

For imagery panels (1, 2 and 4), set `DATA_ROOT` to the external data directory.
The plotting resolver accepts either the original relative tree or unique original
filenames. Support masks generated by `prepare` are under `runs/full/support`; to
use those instead of the original `processed/P1_01/masks` tree, expose that directory
within the external data tree or use the original supported data layout.

```bash
python scripts/figures.py --figure 1
python scripts/figures.py --figure 2
python scripts/figures.py --figure 4
python scripts/figures.py --figure supplement
```

The original formal plotting code writes to `figures/regenerated/`, preserving the
paper's true originals under `figures/`. Its numerical input tables and selected
derived GIS layers/error rasters are packaged for traceable regeneration. No raw
satellite image is bundled. Original plot inputs describe recorded experiments;
the portable pipeline's newly generated outputs are converted explicitly using:

```bash
python scripts/export_figure_inputs.py --work runs/full --output runs/new_figure_inputs
python scripts/figures.py --inputs runs/new_figure_inputs --figure 1
python scripts/figures.py --inputs runs/new_figure_inputs --figure 2
python scripts/figures.py --inputs runs/new_figure_inputs --figure 3
python scripts/figures.py --inputs runs/new_figure_inputs --figure 4
python scripts/figures.py --inputs runs/new_figure_inputs --figure 5
```

The exporter requires all 24 route outputs and 288 GIS cell tables; missing outputs
raise an error rather than falling back to recorded metrics. The original main
plot layouts contain checks and numerical annotations specific to the paper's
recorded results; a materially different full rerun needs discrepancy review before
its plots can be treated as reproductions of those formal figures. Supplements
are regenerated from archived measured runtime/efficiency logs; the new portable
trainer does not claim to recreate the original machine's runtime measurements.

## Verification states

1. Synthetic core verified: import/CLI checks, formula tests and actual disk/model/GIS
   smoke test passed in the available environment.
2. Full workflow verified: requires fresh installation, real-data input preparation,
   formal training/evaluation entry-point checks and figure compatibility validation.
3. Full results reproduced: requires executing all 12 models and comparing all
   formal outputs to the recorded tables, with declared numerical tolerances.

The clean installation, synthetic core, complete real input preparation, recorded
figure regeneration and GIS export schema have been observed. Formal model training
and all downstream steps have not been rerun from scratch as one complete result
reproduction. Machine-readable evidence is in `docs/validation/`. Reproduction can vary
with PyTorch/GEOS/PROJ versions and platforms; CPU determinism does not guarantee
bitwise equivalence across different libraries or hardware.


## Tested Windows environment

`requirements-lock-windows-py311.txt` records the clean accepted environment.
For CPU parity, first install the official wheel then the lock:

```bash
python -m pip install --upgrade pip
python -m pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements-lock-windows-py311.txt
python -m pip check
```

The general `requirements.txt` supports non-Windows environments; the exact lock
records an observed Windows/Python 3.11 environment and is not a cross-platform
bitwise-reproducibility promise. Do not copy `.venv` or `runs` into GitHub.
